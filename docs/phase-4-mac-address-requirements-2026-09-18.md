# 第四阶段增补需求基线：MAC 地址

- 定稿日期：2026-09-18
- 状态：用户已确认；交由“四阶段开发”在已完成的 V022 存量补录与网关调整基础上增量实施。
- 效力：本文件只新增 MAC 地址能力。原 `docs/phase-4-requirements-and-acceptance.md` 中交换机端口规则及 `docs/phase-4-manual-assignment-and-gateway-baseline-2026-09-17.md` 中补录规则继续有效；若无特别说明，MAC 沿用交换机端口的权限、生命周期、审计和交付要求。

## 1. 业务定义

“MAC 地址”指与**一次具体 IP 分配**相关的设备网络接口 48 位硬件地址，不是 IP 地址本身的永久属性。一个分配记录最多保存一个 MAC 地址；允许同一 MAC 出现在多个有效或历史 IP 分配中，不做唯一性约束。无需通过 PING、ARP 或交换机自动探测，管理员人工填写即可。

MAC 是**选填**字段。管理员审批申请并手动分配 IP 时可填写；管理员将存量 IP 逐条“补录已分配”时也可填写。不填不妨碍审批或补录。科技管理员提交申请时不填写 MAC；此功能不改变资产分类、资源编码和使用人字段的条件必填规则。

## 2. 输入、归一化与校验

1. 接受 48 位（12 个十六进制字符）的常见写法：`AA:BB:CC:DD:EE:FF`、`AA-BB-CC-DD-EE-FF` 或 `AABBCCDDEEFF`。英文字母大小写均可输入；只去除整个输入的首尾空白，内部空格、混用分隔符、非十六进制字符、组数/位数错误及 64 位 EUI-64 均拒绝。
2. 服务端统一保存和返回大写冒号格式，例如输入 `aa-bb-cc-dd-ee-ff` 后保存为 `AA:BB:CC:DD:EE:FF`；空白输入等同未填写。前端可即时提示格式，但服务端必须独立校验并返回可理解的中文错误。
3. 只校验上述格式，不额外拒绝重复 MAC、全零地址、组播/本地管理位等；不能凭格式推断设备是否真实在线。

## 3. 生命周期、可见性与修改

1. MAC 随 `ip_assignment` 的这次分配保存，不写入 `ip_address_pool` 作为地址本身的固定值。审批时与分配同事务保存，补录时与手工分配同事务保存。升级前已有分配的 MAC 留空，不从其他字段推测或回填。
2. 只有初始管理员和其他管理员可查看、填写、修改、清空和导出 MAC。科技管理员的“我的申请”“我的 IP”、通知、可访问 API 与导出均不得包含 MAC 字段；直接请求管理员接口应被服务端拒绝。两类管理员权限相同。
3. 管理员可对**当前有效分配**的 MAC 单独修改或清空，不要求修改原因。服务端须校验目标分配 ID 与预期版本仍有效，防止旧页面覆盖后来分配；同值重复保存可按无变化处理。未分配、网关系统保留和已释放历史记录不能创建或修改“当前 MAC”。
4. 每次实际修改或清空记录审计：操作者、时间、分配记录、旧值和新值；审计详情仅按管理员权限展示。MAC 格式归一后无变化不产生虚假变更。
5. IP 释放后，资源池不再显示旧 MAC 为当前值；本次分配与释放历史保留 MAC 快照，已处理申请详情可回看该次分配的 MAC。再次分配同一 IP 时，新记录默认 MAC 为空，不继承历史值。

## 4. 页面与导出

1. 管理员审批确认分配、管理员存量 IP 补录的确认步骤，在 IP、网段、资产及交换机端口附近显示“MAC 地址（选填）”；确认摘要展示归一化后的 MAC 或“—”。输入出错时保留已选择的 IP、资产和已填表单内容。
2. 管理员申请审批详情、IP 资源池当前分配摘要/详情及释放历史可查看 MAC；未填写统一显示“—”。资源池列表要能直观看到当前 MAC，可与端口放在现有“分配摘要”内，避免新增宽表列。修改入口与“编辑 IP 状态”分离；可与交换机端口并列放在分配详情/维护弹窗，不能使原有端口修改功能退化或让操作按钮挤出页面。保存或清空后给出明确反馈并刷新当前行/详情。
3. 管理员数据导出把“MAC 地址”列为可勾选字段，至少适用于 IP 资源池、申请记录、分配记录和释放记录的 CSV/XLSX；资源池导出取当前有效分配 MAC，历史导出取对应历史分配/释放快照。未勾选时不输出该列，沿用字段白名单和公式注入防护。
4. 页面设计与实现须先告知并实际使用 Awesome Design Skill，保持现有管理台风格、ES5/IE11 兼容与窄屏可用；真实浏览器操作验证不可仅由源码字符串检查替代。

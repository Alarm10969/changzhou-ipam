# 第四阶段需求与验收基线：口令规则、交换机端口

定稿日期：2026-09-16。开发起点为第三阶段 V019（提交 `9b0d9ad4671589a7cb39b853fa2d2b103f635ac1`）。本阶段只增加下述两项能力及必要的迁移、页面、测试和交付，不重做既有申请、审批、释放或角色权限。

## 1. 口令规则与旧口令强制修改

### 业务规则

- 新口令长度至少 8 位，同时至少包含一个 ASCII 大写字母 `A-Z`、一个 ASCII 小写字母 `a-z` 和一个数字 `0-9`。保留现有 72 位上限；特殊字符允许但不强制。
- **不增加**常见口令字典、用户名相似度、连续字符、重复字符等额外限制。校验错误应说明缺少长度、大写、小写或数字中的哪一项，不能只提示“弱口令”。
- 管理员创建账号的初始口令、管理员重置口令、用户首次/自助修改口令、首次部署的初始管理员口令，以及本地初始管理员恢复工具生成的新口令，均执行同一规则。原有“重置后首次登录必须修改”“新口令不能与当前口令相同”等规则不变。
- 对升级前已存在的账号，不在迁移时猜测哈希对应的明文，也不无差别要求所有账号换口令。用户**下次成功登录**时，服务端利用刚验证过的登录口令判断是否满足新规则；若不满足，则将该账号标记为必须修改口令，并向客户端返回该状态。未完成修改前，只允许修改口令和退出登录；普通业务页面与 API 均被服务端拦截。合规旧口令不因本次升级被强制修改。已有初始/重置口令的强制修改状态继续有效。
- 前端在创建、重置、修改口令表单旁显示简短规则，并即时提示具体缺失项；后端始终独立校验，不以页面校验替代安全门禁。口令明文不得写入日志、审计、通知或导出。

### 验收场景

1. 7 位、8 位但缺少大写/小写/数字的口令分别被拒绝；满足三类字符且不少于 8 位的口令可用；特殊字符非必需。
2. 新建、重置、修改、初始管理员引导与本地恢复工具使用同一规则；页面与 API 返回一致的中文错误。
3. 升级前弱口令账号使用正确口令登录后只能进入修改口令流程，直接调用业务 API 也被拒绝；改为合规口令后恢复权限，原有其他会话失效规则不变。
4. 升级前已合规的口令仍能正常登录；错误口令仍按原有失败次数与锁定策略处理，不泄露账号是否使用弱口令。

## 2. 交换机端口

### 业务规则

- 字段正式名称为“交换机端口”，指交换机物理/逻辑端口标识，**不是 TCP/UDP 的 1–65535 端口号**。管理员审批并手动选择 IP 时可以填写，非必填；不填写不妨碍分配。
- 端口按字符串保存，去掉首尾空白后最多 64 个字符；空字符串等同未填写。允许常见格式中的字母、数字、斜杠、连字符、下划线、英文句点、冒号，例如 `GE0/0/1`、`Eth-Trunk1`、`1:0:24`。禁止换行和控制字符，不做数字范围校验或唯一性约束；不同设备可以使用相同端口标识。
- 端口归属于**一次具体 IP 分配记录**，不是 IP 资源池地址本身。管理员审批时与分配在同一事务中保存。历史已分配记录升级后端口为空，不补造数据。
- 管理员在申请审批详情和 IP 资源池查看端口。资源池列表应能直接看到当前已分配 IP 的端口（可放在“分配对象”摘要内，避免列表过宽），详情完整显示；未填写统一显示“—”。
- 管理员可在 IP 资源池对**当前已分配**的 IP 单独修改或清空端口，不要求填写修改原因；不能因为现有“已分配 IP 不可编辑状态”的限制而隐藏端口编辑入口。未分配/系统保留地址不可创建无归属端口；已释放历史记录不再修改。修改时服务端校验该分配仍为当前有效分配，避免旧页面覆盖后来分配的数据。
- 每次实际修改记录审计：操作者、时间、对应分配记录、修改前值和修改后值；口令或其他敏感字段不进入该审计。端口清空也视为修改。对相同值重复保存可按无变化处理。
- IP 释放后，资源池不再把旧端口显示成当前端口；已处理申请详情、历史分配及释放历史仍可回看该次分配的端口。再次分配同一 IP 时，新分配的端口独立填写，不继承旧值。
- 科技管理员的“我的申请”“我的 IP”、通知、可访问的 API 响应及导出均不包含端口字段；只有管理员可查看、修改、导出。其他管理员与初始管理员权限相同。
- 管理员导出时，“交换机端口”作为可勾选字段出现在适用的数据类型中，至少包括 IP 资源池、申请记录、分配记录与释放记录；CSV 和 XLSX 均应按既有字段白名单与公式注入防护规则导出。资源池导出取当前有效分配端口，历史类导出取对应历史分配端口。

### 页面与交互要求

- 审批弹窗在“确认分配”步骤、已选 IP 摘要附近设置“交换机端口（选填）”输入框；确认前能看清 IP、网段、分配对象和已填端口。端口错误在弹窗内提示并保留已经选择的 IP。
- 资源池的端口修改使用独立操作，不和“编辑 IP 状态”混用；保存后刷新当前行/查询结果并给出成功或失败反馈。空值展示一致，长端口名不能挤坏表格或遮挡操作。
- 涉及页面设计与实现时，开发任务须先告知并使用 Awesome Design Skill；以实际浏览器操作和窄屏检查验证，不只做源码字符串断言。

### 验收场景

1. 管理员分配 IP 时不填端口、填写 `GE0/0/1` 等合法端口均成功；超长、换行或控制字符被前后端明确拒绝。
2. 管理员在审批详情、资源池列表/详情可见端口；可对当前分配修改、清空，且不填写原因也能保存；审计能查到前后值与操作者。
3. 科技管理员登录后从页面和其可访问 API 均看不到端口；直接调用管理员端口修改/导出接口被拒绝。
4. 释放后资源池不残留旧端口，历史申请/分配/释放记录保留；同一 IP 再分配不会继承旧端口。
5. CSV、XLSX 的适用导出类型均可勾选端口，值与历史一致；未选该字段时不输出该列，且不破坏现有导出字段与公式注入防护。

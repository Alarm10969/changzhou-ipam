## 缺陷

### F-01（P1）：旧资产分类和映射接口仍可写入不可见数据

V017 新页面只读取 `/admin/assets`，但路由仍开放：

- `POST /admin/asset-categories`
- `PUT /admin/asset-categories/{id}`
- `POST /admin/asset-subcategories`
- `PUT /admin/asset-subcategories/{id}`
- `PUT /admin/asset-mappings`

独立接口实测向旧接口创建“V017旧模型残留验证”，HTTP 返回 201、生成旧分类 ID 2；随后查询新 `/admin/assets?includeInactive=1`，该数据不可见。

这会产生管理员无法在当前页面发现、修改或删除的配置，并保留两套资产规则入口。建议 V017 移除或明确禁用旧写接口；若为升级兼容保留只读查询，也应拒绝新增/修改，并补接口回归。

### F-02（P1）：审批列表和详情仍按旧“大类 / 小类”格式展示新资产

新申请在审批列表显示为“验收双关联终端 / 旧数据”，详情也显示同样文本。V017 已不存在小类，“旧数据”会误导管理员认为新申请发生迁移异常。

同时，双关联资产详情把“统一认证号：U0170001资源编码：R-V017-0001”连在一行，缺少换行或分隔符。

根因是后端为旧页面兼容把 `asset_name` 同时别名为 `category`、把 `subcategory` 返回为空字符串，而活动 `applicationsV4` 仍使用旧分类拼接；条件字段拼接资源编码时也没有在已有文本后添加 `<br>`。

建议审批列表和详情直接使用 `assetType + assetName`，并按两个关联开关独立分行展示使用人与资源编码；补浏览器断言，禁止 V017 新记录出现“旧数据”。

### F-03（P2）：页面版本标识仍为 V014

当前 `VERSION.txt` 和构建产物为 `3.4.0 / V017`，但管理员、科技管理员页头均显示 `3.3.1 · V014`。现场无法凭页面确认实际升级版本。

建议版本从构建文件或单一常量生成，不再在 `frontend/app.js` 手工硬编码；发布测试应交叉校验页面标识、`VERSION.txt` 和安装脚本门禁。

### F-04（P2）：新增资产名称为空时没有任何提示

点击“新增资产”但不填写必填资产名称，弹窗保持不变，没有错误提示，也没有把焦点定位到资产名称。用户容易认为按钮失效。

建议在弹窗内显示“请填写资产名称”，并聚焦对应输入框；补页面交互测试。

### F-05（P2）：README 首页仍描述已删除的旧模型

README 开头仍写“资产类型和小类”“未映射小类不能提交”“科技资产正式小类”，与 V017 资产定义和直配推荐网段模型冲突。部署人员会按过期规则验收。

建议同步 README、发布说明和手工测试清单，全文检查“大类、小类、映射、PC 特例”等旧术语，只在历史迁移说明中保留必要描述。

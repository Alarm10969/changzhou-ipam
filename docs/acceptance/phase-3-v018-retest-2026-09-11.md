```text
SELECT count(*) FROM pragma_table_info('ip_application') WHERE name='override_reason'
```

`StageFourBaselineSmokeTest.java:13` 和 `StageFiveRemediationSmokeTest.java:21` 仍断言 `override_reason` 不存在，与 V018 相反。现有测试也没有覆盖“同网段无原因成功、跨网段无原因失败、跨网段有原因成功”的三组业务规则。

### F-02（P1）：页面无法填写改选原因

浏览器实测：管理员打开待审批申请，把最终网段从办公切换为测试，选择候选 IP 并点击“确认分配”。后端正确提示“最终网段与推荐网段不一致，必须填写改选原因”，但审批弹窗没有“改选原因”输入框，用户没有任何途径补填并继续。

`frontend/app.js:994` 的活动审批弹窗只包含最终网段、候选 IP 和审批意见，提交请求也没有 `overrideReason`。

应在最终网段与推荐网段不一致时显示并强制填写原因；切回推荐网段后允许留空。前端校验用于即时反馈，后端校验继续作为安全门禁。

### F-03（P1）：改选原因未进入详情和导出

- 浏览器查看跨网段申请详情，只显示推荐网段、最终网段和审批意见，没有显示已保存的改选原因。
- 仅请求导出 `overrideReason` 时，接口返回 HTTP 400 `EXPORT_FIELDS_INVALID`。
- `PhaseThreeService.allowedV017()` 和导出 SQL 未包含 `overrideReason`。
- 活动导出页面 `exportsV2` 也没有“改选原因”选项。

应将改选原因加入申请、分配和资源池相关导出白名单/SQL，并在审批详情中明确显示；无改选时展示“—”即可。

### F-04（P1）：双关联字段仍然粘连

```text
统一认证号：U-V18-CROSS资源编码：RC-V18-CROSS
```

`frontend/app.js:991` 仍未在已有使用人信息后插入 `<br>`。应将使用人、统一认证号、资源编码显示为三个独立字段，并增加真实 DOM 断言。

### F-05（P2）：审批页面仍残留旧资产模型

浏览器列表及详情仍显示“`双关联回归资产 /`”，资产名称后有多余斜杠。原因是：

- `frontend/app.js:66` 仍把 `assetName` 写回 `category` 并把 `subcategory` 设为空格；
- `frontend/app.js:993`、`1000` 仍按 `category / subcategory` 渲染。

应彻底删除响应兼容层，直接显示“科技资产/非科技资产 + assetName”。查询框占位文字“资源编码或小类”也应改为“资源编码或资产名称”。

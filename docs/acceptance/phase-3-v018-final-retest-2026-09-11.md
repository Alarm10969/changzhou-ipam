## 缺陷

### F-01（P1）：V018 审批候选分页按钮再次被 PING 事件覆盖

活动入口调用 `applicationsV4`。该函数内部后声明的 V018 `candidates()` 会覆盖前一个实现。在 V018 的候选列表渲染完成后，代码先给“上一页”“跳转”“下一页”绑定分页事件，随后又遍历候选区域内的**全部按钮**并统一覆盖为 PING 事件：

```javascript
for(k=0;k<buttons.length;k++)buttons[k].onclick=function(){
  q('POST','admin/ip-pool/'+button.getAttribute('data-candidate-ping')+'/reachability', ...)
}
```

分页按钮没有 `data-candidate-ping`，点击后会请求 `/admin/ip-pool/null/reachability`，正常的上一页、下一页和跳页处理器已经被覆盖。该问题与 V014 前出现过的候选分页回归同类，旧的安全实现实际已经使用属性过滤，但 V018 重写候选弹窗时没有保留过滤条件。

影响：一个 /24 网段约有 253 个候选地址，管理员只能可靠操作第一页，不能完成跨页手动选 IP 的核心审批流程。

修复要求：

1. 只给存在 `data-candidate-ping` 属性的按钮绑定 PING；不得覆盖分页按钮。
2. 删除 `applicationsV4` 中被覆盖的重复 `candidates()`，保留一套明确的活动实现。
3. 增加真实 DOM/浏览器回归：第一页→第二页→末页、跳页、跨页保留选择、切换网段清空选择、PING 后分页仍可用。
4. 自动测试不能只断言源码中存在 `candidateNext` 和 `data-candidate-ping` 两个字符串，应验证事件作用域或执行真实 DOM 点击。

### F-02（P2）：README 仍描述已删除的旧资产模型

`README.md` 第 3 行仍写“资产类型和小类”“未映射小类禁止提交”“科技资产正式小类”等内容，与 V017/V018 的直接资产定义冲突。该旧文本已经进入 V018 压缩包。

正确说明应为：管理员直接维护科技资产或非科技资产下的具体资产，每个资产独立设置“关联使用人”“关联资源编码”和推荐网段；申请时按支行、网点、资产类型、具体资产逐级选择；网点六类网段不完整时禁止提交。

### F-03（P2）：活动页面搜索提示仍使用“小类”

- `applicationsV4` 的查询提示仍为“使用人、认证号、资源编码或小类”。
- `poolV3` 的查询提示仍为“完整 IP、姓名、认证号、资源编码或小类”。

当前模型已不存在小类。从易用性和一致性看，应统一改为“资产名称”，避免管理员继续按旧概念理解系统。

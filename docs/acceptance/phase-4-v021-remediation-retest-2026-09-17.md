1. 新 ZIP 自身大小和 SHA-256 与交付值一致；52 个原始 ZIP 条目没有绝对路径、反斜杠或 `..`；`release-files.sha256` 的 51 项与 `dependencies.sha256` 的 18 项逐项匹配。包内 `VERSION.txt`、前端 `app.js` 和安装脚本均指向 V021。包内 `app.js` 的 Node 语法检查通过。
2. 在全新隔离库上传两行原失败案例：`B9,T7,108.56.80.0/27` 与 `B9,T8,108.56.80.0/24`。预览均提示冲突，本次分别建议 `108.56.75.224/27` 和 `108.56.94.0/24`。独立用 IPv4 地址区间计算：两条建议各自派生的六类网段均避开原有网段，且两组六类网段彼此不重叠。
3. 将上述两条建议**同时**写入同一批次重新上传，返回 `PREVIEW_READY`、错误 0 行；确认返回 `COMPLETED`、插入 2 行；数据库中两个网点各生成六段，共 12 段。原先“建议不能合用”的问题未再复现。
4. 单笔 `/27` `108.56.32.0/27` 推导出第三段 `32、35、43、44、45、47` 的六类网段，网关均为最后可用地址 `.30`；相邻 `108.56.32.32/27` 可生成，网关 `.62`。已有 `/27` 时拟建包含它的 `/24`、已有 `/24` 时拟建落入其中的 `/27`，预览显示冲突，提交返回 `CIDR_OVERLAP`，失败网点无地址段。
5. 冲突的两行批量预览标错 2 行，确认返回 `IMPORT_NOT_CONFIRMABLE`，两行均未写入。另一批先预览成功，再新增占用网段，确认返回 `IMPORT_REVALIDATION_FAILED`，两行均未写入。隔离库外键检查无异常；独立遍历最终 42 个现存地址段，交叉重叠数为 0。
6. V021 启动前后、以及全部测试结束后，对旧库的支行、网点、地址段、IP 池、申请、分配和释放记录的**原有行**逐表做内容哈希，七表均保持一致，旧网关未被自动改写。

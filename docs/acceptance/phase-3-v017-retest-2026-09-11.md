## 未通过项

### F-01（P1）：跨网段审批无需填写原因

已确认规则：管理员允许改选其他网段，但必须填写原因。

实测步骤：

1. 创建推荐网段为 `OFFICE` 的双关联资产申请。
2. 管理员选择 `TEST` 网段候选 IP。
3. 请求中不发送任何改选原因。
4. 审批接口返回 HTTP 204，申请被成功保存为 `TEST`，分配 IP 为 `108.56.13.2`。

代码证据：

- `IpamApplication.java:136` 的审批路由不读取 `overrideReason`。
- `PhaseFourService.java:53` 的审批服务不校验、不保存改选原因。
- `V017__reset_demo_business_data_and_simplify_assets.sql` 重建申请表时移除了 `override_reason`。
- `StageFiveRemediationSmokeTest.java:21` 反而断言该字段不存在。
- `frontend/app.js:994` 的活动审批弹窗没有改选原因输入框，提交请求也不发送该字段。

应恢复端到端规则：申请表保存改选原因；仅当最终网段与推荐网段不一致时强制必填；相同时允许为空；审批详情、审计和导出均应展示；增加同网段成功、跨网段无原因失败、跨网段有原因成功三组回归。

### F-02（P1）：审批页面的双关联字段仍然粘连

`frontend/app.js:991` 中使用人信息末尾没有换行，资源编码分支中的 `(h?'':'')` 无论是否已有内容都为空字符串。因此双关联资产仍会生成：

`统一认证号：U00995538资源编码：PC-CZ-009`

应在已有使用人信息时插入 `<br>`，并增加真实 DOM/浏览器断言，不能只检查源码中是否出现字段名称。

### F-03（P2）：审批资产展示仍依赖旧字段兼容层

- `frontend/app.js:993` 和 `frontend/app.js:1000` 仍使用“category / subcategory”的旧模型渲染。

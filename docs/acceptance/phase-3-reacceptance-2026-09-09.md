## R-01：旧版 PC 记录导致 V013 升级失败（阻断）

复现程序：同目录 LegacyPcUpgradeProbe.java。程序从包内迁移脚本依次构造 V001–V012，写入真实校验和迁移历史，然后插入旧版合法 PC 申请：asset_type=TECH、device_type=PC、asset_code=LEGACY-PC-001，旧版 applicant_name/unified_auth_id 有值，而新版 user_name/user_unified_auth_id 为空。此种数据由原阶段二流程支持，既有 StageTwoSmokeTest 本身也使用了相同形态的 PC 申请。

调用包内真实 Database.migrate 后输出：

    PASS|VALID_V012_LEGACY_PC_INSERTED
    FAIL|LEGACY_PC_UPGRADE|org.sqlite.SQLiteException: [SQLITE_CONSTRAINT_CHECK]
    AFTER|applications=1|V013=0

根因：V013 新表强制所有 PC 具有新版使用人字段，INSERT ... SELECT 原样复制旧记录，没有兼容旧版 PC 的身份字段。新表约束拒绝复制，升级事务回滚。旧记录保留，V013 未登记，但启动迁移不能完成。

修复要求：设计明确的旧记录兼容策略，保留原字段及历史含义，不应未经依据把“申请人”猜成“PC 使用人”。可以保留可辨识的历史数据例外并提示待补录，同时对新提交严格校验。补充带旧 PC、分配、通知及释放关联的 V012→新版真实迁移测试，并验证重启、外键完整性与历史数据保留。现有 Stage Five 从空库升级，未覆盖这个分支。

复现命令（PowerShell，替换为解压后的包目录；数据库路径必须是尚不存在的测试文件）：

    java -cp "$packageRoot/ipam-stage3.jar;$packageRoot/lib/*" docs/acceptance/LegacyPcUpgradeProbe.java "$packageRoot/ipam-stage3.jar" "$env:TEMP/unique-legacy-pc-test.db"

## R-02：审批候选 IP 只能选择前 50 个（重要）

浏览器打开一笔推荐办公网段的 PC 申请，弹窗显示“共 253 个可用 IP”，实际只有 50 个单选按钮，地址为 108.56.15.2–108.56.15.51，没有上一页、下一页、页码或跳页入口。其余 203 个可用地址无法从页面选取。

根因：frontend/app.js 的活动 applicationsV3 中，drawCandidates 只渲染表格，未保留 V2 的分页组件；currentPage 固定初始化为 1，且只在切换网段时重置为 1。后端分页仍存在。

修复要求：恢复候选分页、页码和跳页，展示总数与当前页范围；覆盖超过 50 个候选的浏览器用例，实际选取第二页或最后一页的 IP 并完成审批，同时验证切换网段后清空旧选择。不得仅通过“第一页可以审批”的测试判定修复完成。

## 使用角度的改进建议

已阅读 Awesome Design 技能目录，将建议定位为界面审查与操作反馈改进；未安装额外设计工具，未改动页面。以下建议来自本次页面操作和截图。

1. 审批确认按钮改为“确认分配”，在提交区域持续显示“申请人 / 网点 / 最终网段 / 已选 IP”。当前按钮为“保存修改”，操作含义不够明确，审批弹窗也缺少申请对象摘要。
2. 网段切换控件放在候选列表上方，分配意见和确认按钮放在列表下方。用户应先确定网段，再选择 IP，减少选完又切换导致重选的往返。
3. 保存状态、审批和驳回成功后显示具体成功提示。当前列表和角标会更新，但没有明确完成反馈；例如“已将 108.56.11.2 设为停用”“已分配 108.56.15.2”。
4. 历史详情突出最终 IP、在用/已释放状态，提供复制 IP/配置摘要操作。驳回记录可收起不适用的分配时间、最终网段等空字段；桌面详情目前文字集中在左侧、右侧空白较大，可改为整齐的标签和值分组。
5. 发布版本应递增，并在页面展示版本/构建标识。整改包和上一包同为 3.3.0，现场仅凭版本号难以确认是否已升级到修复版；至少同时展示构建时间、迁移版本或提交短号。

# V021 六类网段规划升级说明

版本：`3.6.0-v021-network-overlap`。目标环境仍为麒麟 ARM64、Java 11、单机 SQLite。本次没有新增数据库迁移，不自动修改任何已有地址段、网关或 IP 池。

## 生效规则

- 六类偏移 `0、3、11、12、13、15` 按第三段计算，即每级移动 256 个 IPv4 地址。生产 `/27` 为 `108.56.32.0/27` 时，网络管理为 `108.56.35.0/27`，网关为 `108.56.35.30`。
- 生产网段可处于任何合法的 `/24` 至 `/30` CIDR 起点，不再检查 `/20`、`/23` 等“规划块起点”。仍要求六段前缀一致、地址都在 `108.56.0.0/13` 内。
- 六段生成的网关固定为各段最后一个可用地址。旧规则表的 `gateway_host_offset` 和 `outlet_block_prefix` 保留供历史兼容，不再决定生成结果。
- 单笔预览、单笔创建、批量预览和批量确认均按实际 IP 起止范围比较，能发现 `/24` 与 `/27` 的包含交叉，不再只比较 CIDR 文本。软删除地址段不参与占用；未删除地址段即使停用仍视为占用。
- 冲突提示包括本次网段、已有网段及其支行/网点，批量导入还包括相冲突的导入行。推荐值是距离原生产网段最近、同前缀且六段全部无冲突的生产网段；同距离优先向高地址方向。批量预览按行顺序预留已给出的六段推荐值，后续行同时避让现有网段、原文件各行及先前建议，保证同批多行建议可以一起使用。推荐是预览时的建议，真正写入前会重新校验。
- 已有地址段的网关和池状态不自动改写。部署前后可正常保留历史业务数据。

## 验收重点

1. `/27` 生产 `108.56.32.0/27` 推导网络管理 `108.56.35.0/27`、网关 `108.56.35.30`。
2. 同一 `/24` 内相邻 `/27` 网点可分别使用 `.0/27` 和 `.32/27`，不因规划块起点被拒绝。
3. 已存在 `/27` 时，拟新增包含它的 `/24` 应提示两侧 CIDR、网点归属与可用建议；反向包含同样应拒绝。
4. 批量模板中两行跨前缀交叉时，两行均列出冲突；整批不得写入。预览后数据库发生变化时，确认必须重新校验并拒绝。
5. 对相互冲突的两行同时采用各自行内推荐值，重新预览须无网段交叉并可原子生成全部 12 段；页面顶部须显示 `3.6.0 · V021`，与 `VERSION.txt` 一致。
6. 使用旧数据库执行升级，确认支行、网点、既有网段与分配记录未被重算或删除；完成麒麟 ARM64 与 IE11/奇安信实机验收。

## 安装边界

发布 ZIP 解压至既有 `/data/项目/IP管理系统` 后，执行 `sh ./deploy/install-stage3.sh`。脚本校验文件和依赖、停止旧实例、备份数据库、运行 ARM64 预检、启动并检查健康接口与版本。完整的一行安装命令和本次 ZIP SHA-256 由交付时提供。不要在有业务使用的生产机上跳过备份或直接替换数据库。

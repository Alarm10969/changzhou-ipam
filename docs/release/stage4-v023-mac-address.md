# V023 MAC 地址发布说明

版本：`3.8.1-v023-mac-address`
数据库迁移：`V021__mac_address.sql`

本包是首轮 V023 独立验收后的修订版；首轮报告作为历史证据保留，修订基线与报告一并随包进入 `docs/` 供追溯。

## 本次交付

- 管理员审批确认和“补录已分配”可选填写 MAC 地址；支持冒号、连字符、12 位无分隔符输入，保存为大写冒号格式。
- MAC 存储在 `ip_assignment`，不做唯一约束，不回填既有分配；当前有效分配可单独编辑或清空，并使用分配编号和版本号防止覆盖并发修改。
- 释放事件保存 MAC 快照；同一 IP 重新分配时新 MAC 默认为空。
- MAC 编辑、清空和释放快照均保留管理员审计；相同规范化值是幂等无审计操作。
- 科技管理员的申请、本人 IP、通知和页面不返回 MAC；管理员资源池、审批历史、当前详情、释放历史和管理员导出可见。
- POOL、APPLICATION、ASSIGNMENT、RELEASE 的 CSV/XLSX 均可选择 `MAC 地址` 字段，未选择时不输出该列。

## 升级与回滚

V020 数据库升级时只执行两条可回滚的 nullable `ALTER TABLE`：为 `ip_assignment` 和 `ip_release_event` 增加 `mac_address`。既有行保持 `NULL`，不会根据资产或历史记录猜测 MAC。安装脚本在迁移前创建带时间戳的数据库备份；升级失败时保留原数据库和备份，不应手工删除或覆盖原库。

回滚时停止服务，将安装前备份恢复为 `data/ipam.db`，再启动上一版 V022 包。V022 不认识 MAC 字段，但不会影响其原有端口、补录、网关和释放历史字段。

## 验证边界

Windows 隔离数据库完成阶段 1–12、MAC 专项后端回归、Edge 真实浏览器回归、ES5 语法和打包文件校验。当前未在麒麟 ARM64、IE11 或生产数据库上执行实机验收；这些仍需独立验收。

# V029 分行独立部署与首次使用

适用版本：3.13.0-v029-branch-setup。目标：麒麟 ARM64、Java 11，单机单实例、本地 SQLite 数据目录。当前交付不代表已在其他分行服务器或所有终端浏览器完成验收。

## 首次部署

1. 由运维准备服务器固定内网 IP、Java 11、可写安装目录和数据目录。确认使用端口可达且未被占用，准备 `unzip`、`sha256sum`、`curl` 或 `wget`。
2. 将分行交付 ZIP 解压到准备好的目录；推荐 `/data/项目/IP管理系统`，也支持其他绝对路径。不要复制其他分行的 `data`、数据库、账号或备份。
3. 进入解压目录，执行 `sh ./deploy/configure.sh`，依次输入监听地址、端口、数据目录。默认监听 `0.0.0.0`，端口 `18080`，数据保存在安装目录下的 `data`。该工具只生成配置，不修改服务器网卡或防火墙。
4. 执行 `sh ./deploy/install-stage3.sh`。脚本校验发布文件、运行环境、启动服务并检查健康接口。首次启动按提示设置初始管理员及密码，密码至少 8 位、含 ASCII 大写、小写和数字。已有管理员时不再提示初始密码。
5. 用终端浏览器访问 `http://服务器实际IP:端口/`，登录并修改初始密码。不能用 `0.0.0.0` 作为访问地址。
6. 打开“首次使用向导”，依次确认地址规则、机构与资产、账号与地址池、检查与试运行。

## 配置文件与优先级

安装根目录 `ipam.conf` 保存本机配置。部署包只含 `deploy/ipam.conf.example`，不会覆盖已有 `ipam.conf`。格式为每行 `KEY=value`，不要加引号、不要在等号两侧加空格、不支持命令、变量展开或行尾注释。目录名本身可以含空格和中文。配置里不能写密码。

```text
IPAM_BIND=0.0.0.0
IPAM_PORT=18080
IPAM_DATA_DIR=/data/项目/IP管理系统/data
```

可选 `IPAM_INSTALL_DIR` 用于约束安装目录，默认当前解压目录。环境变量覆盖配置文件；配置文件覆盖默认值。排查配置未生效时，先检查当前终端是否仍有旧的 `IPAM_*` 环境变量。可用 `IPAM_CONFIG_FILE` 指向同一份其他位置的配置，但后续所有维护命令都须传入同一路径。

修改端口或绑定地址前，执行 `sh ./deploy/stop-stage1.sh`；编辑文件后执行 `sh ./deploy/start-stage1.sh`。健康检查会跟随绑定地址。若监听 `127.0.0.1`，仅服务器本机可直接访问；若监听某个具体地址，该地址必须已配置在服务器网卡上。

数据目录不要只改配置就启动，否则会打开另一套数据库。迁移目录须先停服、备份并搬迁完整数据，核对后统一更新各维护入口。原目录的业务数据不会自动搬迁。

## 首次使用向导

1. 地址规则：填写本行管理的单个 IPv4 CIDR 范围、默认网段前缀 `/24` 至 `/30`、DNS、六类网段名称及偏移。初始范围仍保留原产品默认值供核对，不代表适用于本行。保存需填写说明，生成规则版本并记录审计。范围变更必须覆盖所有未删除的已有网段；不会重算旧地址池。
2. 机构与资产：建立启用支行、所属网点和资产定义。核对使用人、统一认证号、资源编码是否必填以及推荐网段。打开管理页面后可通过顶部按钮返回向导。
3. 账号与地址池：建立科技管理员，为首个试运行网点预览并生成六类地址段。六类网段按 256 地址步进派生，生产网段及全部派生网段必须落在本行范围内。当前仍采用六类规划模式，不支持任意数量的网络类型。冲突时的推荐搜索仅检查周边有限候选，未给出建议不代表整个管理范围已用尽。
4. 检查与试运行：后端实时核验规则确认、启用机构、资产、科技管理员及至少一个完整六类网点地址池。缺项不能确认完成；原先已完成后停用机构或账号，也会重新显示缺项。向导可中断后继续，不强制阻断已有系统业务。

“准备完成”只表示具备首个网点试运行条件，不代表全部网点初始化完成或真实网络已验收。请完成一次申请、审批、查看分配、释放与备份，再逐步导入其他网点和存量设备。向导不会自动创建业务样例或修改网络设备。

## 现有 V028 系统升级

先在网页下载完整备份，保留旧版发布包。使用原停止脚本正常停服，再解压 V029 包覆盖程序文件。不要删除或替换原数据目录，也不要覆盖已存在的本机配置。

已有 `IPAM_PORT`、`IPAM_BIND`、`IPAM_DATA_DIR` 自定义值时，先按原值创建 `ipam.conf`，再执行 `sh ./deploy/install-stage3.sh`；未配置时继续使用 `0.0.0.0:18080` 和安装目录下 `data`。旧版脚本不读取新配置，升级前停服仍须使用原来的环境变量和数据目录。

V029 无新增数据库迁移，沿用 V001–V023；已有地址规则、分配及历史保留。仅在管理员主动保存新规则时改变全局范围。首次使用向导为新增入口，旧系统不强制重新初始化。退回旧程序时必须恢复配套升级前数据库；旧程序不支持 V029 自定义地址范围，不能直接拿新配置库降级运行。

## 管理员忘记密码

原密码不可查看，数据库只保存 BCrypt 校验摘要。先查看浏览器是否保存过该系统密码。无记录时在安装目录依次执行：

```sh
sh ./deploy/stop-stage1.sh &&
sh ./deploy/recover-admin.sh &&
sh ./deploy/start-stage1.sh
```

恢复脚本重设初始管理员密码、撤销其会话、保留业务数据，并要求登录后再次改密。停止失败时不要继续。密码不要写在命令、配置或工作记录中。

## 日常维护

启动：`sh ./deploy/start-stage1.sh`。停止：`sh ./deploy/stop-stage1.sh`。离线备份、恢复和管理员恢复也读取同一配置。配置文件属于服务器环境信息，网页业务备份不会包含它，应另行妥善保存；业务规则及向导进度保存在数据库中，随完整业务备份恢复。

当前脚本以后台进程方式启动，不自动注册系统服务或开机启动。服务器重启后由运维启动并检查健康接口。需要开机启动时，应按本行服务器服务管理制度配置并验收，不要重复运行多个实例。

## 分行交付包内容

仅包含程序 JAR、离线依赖、前端、部署脚本、版本与摘要清单、本说明；不包含 `data`、业务数据库、备份、个人配置、日志和本行台账文件。账号在目标服务器首次启动时创建。分行包与常规升级包使用同一程序；分行包文档精简，适合交给新部署单位。

# V022 手工补录与网关调整发布说明

版本：`3.7.0-v022-manual-assignment-gateway`。目标运行环境仍为麒麟 ARM64、Java 11、单机 SQLite。本版本在 V021 六类网段规划和交叉占用检查基础上增加 V020 数据迁移。

## 本次新增

- 管理员可在资源池的可用、停用、人工保留地址上执行“补录已分配”。服务端动态校验当前启用资产定义：只有定义要求资源编码或使用人时才要求对应字段。
- 补录记录保留资产类型/名称/关联规则快照、来源状态、登记人、登记时间、可选责任科技管理员、交换机端口和说明，不创建虚构 `ip_application`。
- 责任科技管理员只能查看和释放分配给自己的补录地址；未指定责任人时不会出现在科技管理员“我的 IP”。科技管理员响应不返回交换机端口。
- 管理员可在资源池的当前网关行执行独立“调整网关”。目标必须是同一地址段的已有主机且无有效分配；旧网关恢复可用，新网关成为系统保留。操作具有事务性、幂等性，并写入旧/新网关和状态审计。
- 释放补录地址后恢复补录前的可用、停用或人工保留状态；释放历史、资源池、统计、查询和管理员导出均区分正常审批与手工补录来源。

## 迁移与回滚

启动时会在 V019 后执行 V020。V020 为 `ip_assignment`、`ip_release_event` 和 `user_notification` 增加可空申请引用及手工来源快照，并对已有记录标记为 `APPLICATION`。升级前由安装脚本生成数据库备份；失败时保留备份和旧工作目录，不自动删除用户文件。

## 验证边界

Windows 隔离 SQLite、Java 11 编译、阶段 1–11 回归、真实 Edge DOM/窄屏回归已覆盖；麒麟 ARM64 原机、IE11/旧版 Edge、真实 DHCP/路由器切换和生产数据升级仍需在目标环境独立验收。本说明不代表最终验收通过。

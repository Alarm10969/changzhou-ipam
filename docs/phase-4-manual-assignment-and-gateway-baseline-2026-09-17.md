## 1. 业务目标与边界

大量 IP 已在现实中投入使用，但系统尚无对应分配记录。管理员需要从 IP 资源池逐条登记真实分配关系，不经过科技管理员发起申请，也不伪造审批。另因网关地址可能登记错误，管理员可以把同一地址段内的“系统保留／网关”标识转移到正确 IP。两项操作必须分开，不能把网关当作普通终端 IP 直接补录。

本轮只支持单条 IP；不做批量补录，不要求填写历史实际分配日期，不自动配置交换机或修改真实网络设备。

## 2. 存量 IP 补录为“已分配”

### 2.1 入口和状态

1. 只有初始管理员及其他管理员可操作。资源池中对未分配的 `AVAILABLE`（可用）、`DISABLED`（停用）、`MANUAL_RESERVED`（人工保留）提供独立的“补录已分配”入口。`ASSIGNED` 不允许重复补录。
2. `SYSTEM_RESERVED` 是当前网关标识，不得经普通补录转为终端“已分配”。如果地址标错为网关，须先通过第 3 节“调整网关”把标识移走；原地址变成可用后才能补录。此规则取代此前“系统保留可直接转换为已分配”的笼统说法。
3. 补录后，资源池当前状态显示“已分配”，该 IP 不再出现在普通审批可选列表。管理员仍可按既有权限查看、释放与维护本次分配的交换机端口。

### 2.2 补录表单

1. 从资源池选定单个 IP；支行、网点、地址段、网段用途和具体 IP 由该资源池记录确定并只读展示，不让管理员填写互相矛盾的归属。已停用或人工保留的来源状态须明显提示。
2. 管理员选择“科技资产／非科技资产”，再从对应的**已启用**资产小类中选择具体资产。沿用现有资产定义，不自行新增分类或把网段用途当作申请人必填项。
3. 按所选资产定义的 `requires_resource_code`、`requires_user` 标志动态校验：要求资源编码的资产必填资源编码；要求使用人的资产必填使用人姓名和统一认证号；不要求的字段不得被额外强制。PC 仍遵守现有“需使用人、无需资源编码”的规则。
4. 可选填“负责的科技管理员”，仅能选当前有效且与该网点权限匹配的科技管理员；不选则为管理员管理的存量分配。该字段不是申请人，不能生成虚构的申请账号或申请时间。已选择的负责科技管理员可在其权限范围内查看该 IP 并按既有规则直接释放；未选择的记录不得错误出现在任意科技管理员的“我的 IP”中。
5. 可选填交换机端口，使用已定稿的端口格式、管理员可见性和修改规则。可选填补录说明／原因；**不要求原因**，也不要求输入历史分配日期。系统记录本次补录时间与操作管理员，明确它是“系统登记时间”，不冒充现实中的原始分配时间。
6. 保存前展示 IP、支行／网点、地址段、资产小类、条件必填信息、负责科技管理员和来源状态的确认摘要；保存失败保留输入并给出明确错误。

### 2.3 数据与一致性

1. 正常申请审批分配与管理员手工补录必须有可区分的来源，例如 `APPLICATION` 与 `MANUAL_REGISTRATION`。历史申请仍与真实 `ip_application` 关联；手工补录不得造一笔“已审批申请”、伪造科技管理员申请人或以空壳申请满足旧表非空约束。允许通过安全迁移调整分配关联或增加专用补录记录，但须保留完整旧库历史。
2. 补录应保存资产类型／小类及必要字段快照、IP 与网段归属、操作管理员、系统登记时间、可选负责科技管理员、可选说明、来源状态和可选交换机端口，确保资产字典后续修改不破坏历史展示。
3. `DISABLED`、`MANUAL_RESERVED` 补录后的当前状态由有效分配覆盖；释放此条分配后恢复补录前的底层停用／人工保留状态，不能误变成可用。`AVAILABLE` 来源释放后恢复可用。此项利用原状态保留或显式快照实现，不能依赖页面推断。
4. 使用单个短写事务及现有 SQLite 并发策略，服务端在提交时重新检查资源池记录、未删除地址段、当前网关标识和有效分配；两个管理员同时补录同一 IP 只能成功一笔。发生过期状态／冲突时返回明确提示，不能产生双重有效分配或部分写入。
5. 手工补录与正常审批分配在资源池、分配记录、统计、查询、CSV/XLSX 导出及释放历史中一致可见，但“申请记录／已处理申请”不凭空多出一条申请。导出应能区分来源、补录管理员和系统登记时间；手工补录的申请人／申请时间显示为空或“—”，不可用补录管理员冒充科技管理员申请人。科技管理员响应及导出仍不得暴露交换机端口。
6. 若选择负责科技管理员，其“我的 IP”及释放权限应对这条补录分配生效；必要通知使用现有站内通知机制且不能依赖不存在的申请 ID。未选择负责人的分配只由管理员处理。释放与审计须显示来源、操作者和对应分配，不删除历史。既有正常申请跨网段审批须填原因的规则不变；补录说明选填与之无关。

## 3. 调整网关标识

1. 在资源池／地址段提供仅管理员可用的独立“调整网关”操作，显示当前地址段、当前网关和同段候选 IP。它不是“编辑 IP 状态”下拉选项，也不是一次普通 IP 分配。
2. 新网关必须是**同一地址段**内真实存在、未删除、未被有效分配占用的主机地址；网络地址、广播地址、跨段地址、已分配地址均拒绝。候选原来为可用、停用或人工保留时，只要满足上述条件即可改为网关；界面应提示其原状态会被“系统保留”覆盖。若旧网关已存在异常有效分配，拒绝并提示先处理异常。
3. 确认后，在一个 SQLite 短写事务中更新 `ip_range.gateway` 及旧／新两个 IP 的保留和启用标识。新网关成为唯一的 `SYSTEM_RESERVED`，禁止普通终端申请或补录；旧网关**直接变为 `AVAILABLE`**，不自动分配、不转为停用待核实。若任一步失败则全部回滚。
4. 记录审计：操作者、时间、地址段、旧／新网关、两地址原状态及可选说明。说明／原因不必填。调整后资源池、地址段详情、相关导出及可选 IP 列表立即以新网关为准；刷新旧页面后不得覆盖更新。重复选择当前网关不产生虚假变更。
5. 只调整本地址段现存网关，不重算同网点其他五段，也不修改全局“新建地址段默认取最后可用地址”的规则；不会配置现实网络设备。页面须明确提醒管理员另行核对实际网关与 DHCP／路由配置。

## 4. 页面与权限

- 资源池的“编辑状态”“补录已分配”“调整网关”“修改交换机端口”保持为语义清楚的独立动作。对不同状态给出可操作入口或原因提示，避免点了无反应；完整字段可放详情／抽屉，列表保持可读。
- 管理员在补录和网关调整前看到影响摘要，完成后看到成功反馈并刷新当前查询。科技管理员不能看到或调用两个管理员操作；负责科技管理员的个人列表只显示授权数据。
- 任何涉及页面设计的实现，开发者须先说明并实际使用 Awesome Design Skill；同时做真实浏览器交互、窄屏与现有目标浏览器兼容检查，不能只靠源码字符串测试。
- 服务端独立进行角色、归属、字段、状态、并发校验；保留审计、CSRF／会话保护、导出字段白名单与公式注入防护。

## 5. 最小验收矩阵

1. 可用、停用、人工保留各补录一笔，资源池显示已分配；已分配重复补录和当前网关直接补录被拒。对应释放后分别恢复可用、停用、人工保留。
2. 对不同资产定义覆盖“仅资源编码”“仅使用人”“两者都要”“两者都不要”，PC 与非科技资产按既有定义校验；前后端一致。无负责科技管理员、无说明、无端口也能成功。
3. 选负责科技管理员后只进入其“我的 IP”并可直接释放；未选时不泄露给任一科技管理员。补录不增加申请记录，不伪造申请人／申请时间，分配和导出可追溯补录人、来源、时间及资产。
4. 同段新网关来自可用、停用或人工保留时，旧网关均变可用，新网关均变系统保留且不可分配；跨段、网络／广播、已分配、删除或过期目标拒绝；事务失败无半套状态。重复调整幂等。
5. 正常申请审批、跨网段原因、交换机端口仅管理员可见、强制／直接释放、统计、搜索、CSV/XLSX、迁移旧库与原有阶段回归均不退化。并发补录只能有一笔有效分配。

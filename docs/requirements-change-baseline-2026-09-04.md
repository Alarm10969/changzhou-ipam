# IP 资产审批分配系统需求变更基线

- 文档版本：1.0
- 基线日期：2026-09-04
- 适用阶段：第三阶段增补开发
- 当前代码起点：`cb26417 fix: 调整资源池全局查询逻辑`
- 状态：已确认，作为本轮开发、测试和交付的唯一需求依据

## 1. 文档效力

1. 本文档高于此前架构文档、阶段三需求文档、发布说明及口头提示中与本文冲突的内容。
2. 未被本文变更的既有要求继续有效，尤其包括：初始管理员保护、管理员权限、科技管理员直接释放、审计、离线部署、SQLite 单实例边界以及 IE11/奇安信兼容要求。
3. 当前每套系统只服务一个分行，只维护一套全局地址规划和资产映射规则，不建设多租户或多规则并行能力。
4. 科技资产分类表尚未提供。除已确认的 `PC` 规则外，禁止开发人员自行编造科技资产小类；系统应先提供可配置能力，待分类表补充后再导入或初始化正式数据。

## 2. 变更目标

本轮将“一个网点绑定一个地址段”调整为“一个网点必须完整绑定六类地址段”，并同步改造申请、审批、IP 资源池、设置、导出和诊断能力。系统应自动推荐目标网段，但保留管理员在特殊情况下改选网段的受控能力。

## 3. 优先级与实施顺序

| 优先级 | 内容 | 完成条件 |
| --- | --- | --- |
| P0 | 修复 IP 资源池“编辑状态”点击无反应 | 根因明确、修复、记录 `memory.md`，并通过浏览器回归 |
| P0 | 数据模型和迁移可安全升级 | 旧库升级不丢历史，迁移清单、测试和发布包同步 |
| P1 | 六网段、设置、分类映射、申请审批改造 | 业务规则和验收用例全部通过 |
| P1 | 资源池详情、逐行 PING、审批历史和完整导出 | 页面、接口、安全和导出验收通过 |
| P2 | 交付包与自动部署 | ZIP、校验值、固定目录部署指令及手工测试说明齐全 |

P0 未通过时不得生成或宣称最终交付包可验收。

## 4. 地址规划与网点绑定

### NET-01 全局可用范围

- 系统只有一个全局可用地址范围：`108.56.0.0/13`。
- 实际覆盖范围为 `108.56.0.0` 至 `108.63.255.255`。
- 新建或导入的任何网点地址段必须完整落在该范围内。
- 地址计算必须使用 IPv4 整数/CIDR 运算，禁止通过字符串拼接或只修改第三段数字实现。

### NET-02 六类地址段

每个网点必须同时具备以下六类地址段，缺少任何一类都视为配置不完整：

| 类型代码 | 中文名称 | 相对生产网段偏移（以 `/24` 为单位） |
| --- | --- | ---: |
| `PRODUCTION` | 生产 | 0 |
| `NETWORK_MANAGEMENT` | 网络管理 | 3 |
| `EXTENSION` | 扩展 | 11 |
| `MONITORING` | 监控 | 12 |
| `TEST` | 测试 | 13 |
| `OFFICE` | 办公 | 15 |

示例：生产网段为 `108.56.0.0/24` 时，系统生成：

- 网络管理：`108.56.3.0/24`
- 扩展：`108.56.11.0/24`
- 监控：`108.56.12.0/24`
- 测试：`108.56.13.0/24`
- 办公：`108.56.15.0/24`

默认情况下，一个网点占用一个 `/20` 规划块，其中每类地址段为 `/24`。生产网段须位于该 `/20` 块的起始 `/24`；系统必须校验对齐、越界和与其他网点的重叠。

### NET-03 自动生成与原子性

- 单个新增：管理员选择支行、网点并填写生产网段，页面先预览六类地址段，确认后一次性创建六段及对应 IP 池。
- 批量导入：新模板一行代表一个网点，填写支行、网点和生产网段；预览必须展开显示将生成的六类地址段。
- 六段创建、IP 池生成和配置版本快照必须在同一个 SQLite 短写事务中完成。
- 任一地址段越界、重叠、重复、格式错误或网点关系错误时，整组/整批不得写入。
- 网络地址和广播地址不得进入可分配池；网关按当时生效的全局规则保留。

### NET-04 旧数据处理

- 用户将删除旧地址段后重新导入，因此本轮不自动猜测或转换旧的一对一地址段关系。
- 数据库升级不得物理删除历史申请、分配、释放事件或审计记录。
- 迁移应兼容旧库启动；尚未重导为六段的网点应明确标记为“配置不完整”，且不得用于新申请。
- 删除旧地址段前须提示备份及对待审批/已分配数据的影响。存在有效分配时不得静默物理删除。

## 5. 全局设置模块

### SET-01 设置范围

管理员“设置”模块至少包含：

- 全局地址范围，默认 `108.56.0.0/13`；
- 网点规划块前缀，默认 `/20`；
- 单类地址段前缀，默认 `/24`；
- 六类网段的名称、代码、启用状态和相对偏移；
- 默认网关生成规则；
- 默认主 DNS、备 DNS；
- 科技/非科技资产分类；
- 资产小类到推荐网段类型的映射；
- 配置版本、启用时间、修改人、修改时间和修改原因。

### SET-02 配置生效规则

- 当前系统同一时刻只能有一套生效的全局规则。
- 修改网络规划规则前必须预览影响并填写原因。
- 新规则只影响之后新建的网点地址段和之后提交的申请；不得自动改写既有地址段、既有申请或既有分配。
- 地址段和申请均应保存所用规则/映射版本快照，以便追溯。
- 删除已被历史数据引用的分类、网段类型或映射时采用停用/软删除，不得破坏历史展示。

## 6. 资产分类与申请表单

### APP-01 申请步骤

科技管理员按以下顺序填写：

1. 选择支行；
2. 选择该支行下的网点；
3. 选择“科技资产”或“非科技资产”；
4. 选择对应设备小类；
5. 根据规则填写条件字段；
6. 查看系统推荐的目标网段类型并提交。

申请人不得选择生产、办公、测试、监控、网络管理或扩展等网段用途。

### APP-02 条件字段

| 资产情况 | 资源编码 | 使用人姓名 | 使用人统一认证号 |
| --- | --- | --- | --- |
| 科技资产 - PC | 不填写 | 必填 | 必填 |
| 科技资产 - 非 PC | 必填 | 不填写 | 不填写 |
| 非科技资产 | 不填写 | 不填写 | 不填写 |

- 非科技资产不要求 MAC、部门、负责人和备注。
- “申请人信息”是当前登录的科技管理员，由系统自动记录账号、姓名和申请时间，不提供手工输入框。
- 统一认证号按现有系统规则校验。

### APP-03 非科技资产分类

`非科技资产确认表.xlsx` 只作为大类/小类字典，不采用其中其他业务字段。初始分类如下：

- 安防保卫设备：VOIP 对讲、视频监控、报警主机、网络摄像机、门禁系统、联动门、其他；
- 渠道运营设备：清分机、本外币一体点验钞机、点钞机、智慧银行设备、智能机器人、智能迎宾机器人、基金托管库系统、智能卡库、智能展示窗、联网信息发布终端、电子广告屏、电子门楣等、其他；
- 行政办公设备：打印复用传真一体机、考勤机、后勤打卡机、其他；
- 其他：其他。

### APP-04 映射与禁止提交

- 系统根据“资产类别 + 小类”的当前有效映射生成推荐目标网段。
- 申请提交时保存推荐网段类型和映射版本快照。
- 小类没有配置有效映射时必须禁止提交，不得默认落到生产网段或任一其他网段。
- 页面明确提示：“该设备小类尚未配置目标网段，请联系管理员在设置 → 资产与网段映射中完成配置。”
- 网点未完整生成六类地址段时也必须禁止提交，并明确指出缺失类型。

## 7. 管理员审批与 IP 分配

### APR-01 推荐网段与改选

- 审批详情显示系统推荐网段类型、映射版本和对应网段。
- 管理员默认在推荐网段内选择 IP。
- 特殊情况下允许管理员改选该网点的其他网段类型；改选后必须填写原因，否则禁止确认分配。
- 系统记录原推荐类型、最终类型、修改人、原因和时间。

### APR-02 手动选择 IP

- 管理员通过可搜索、可分页的单选表格弹窗手动选择具体 IP，不使用超长下拉框，也不得由系统自动代选。
- 候选 IP 只能来自申请网点的最终目标网段，且状态必须可用。
- 提交审批时后端必须再次校验网点、网段类型和 IP 状态，防止并发占用及绕过前端。
- 分配、申请状态、审计等更新必须在同一短写事务内完成。

### APR-03 已审批明细

- 申请审批页至少提供“待审批、已通过、已驳回、全部”视图或等效筛选。
- 已处理申请仍可打开详情，展示申请人、申请时间、资产大类/小类、条件字段、推荐网段、最终网段、改选原因、分配 IP、审批人、审批时间和审批意见。

## 8. IP 资源池页面

### POOL-01 查询与展示

- 支行、网点为可选范围条件；选择支行后网点级联。
- 不设置需要用户再次选择的地址段下拉框。选择网点后，六类地址段作为只读信息或类型筛选展示。
- 全局搜索支持 IP、资产小类、资源编码、使用人姓名和统一认证号。
- 主表优先展示：支行/网点、网段类型、CIDR、IP、当前状态、分配摘要、PING 结果、操作。
- 详细信息使用弹窗或抽屉分组展示，避免把所有字段塞入主表。

分配摘要规则：

- 科技非 PC：设备小类 + 资源编码；
- PC：PC + 使用人姓名 + 统一认证号；
- 非科技：大类 + 小类；
- 未分配：显示“—”。

### POOL-02 P0 编辑状态缺陷

当前已知缺陷：在 IP 资源池点击“编辑状态”没有反应。

修复验收要求：

- 先在真实页面复现并记录根因，不得只通过阅读代码猜测结论；
- 对允许编辑的地址，点击后必须立即出现带当前值的编辑弹窗/抽屉；
- 可修改为“可用、停用、人工保留”，人工保留必须填写原因；
- 保存成功后刷新当前页并显示成功提示，失败时显示可理解的错误信息；
- 已分配和系统保留地址不可编辑时，按钮应明确禁用并可见说明原因，不得保留一个点击无反应的伪按钮；
- 无 JavaScript 控制台错误、无重复提交；接口继续校验权限、CSRF、合法状态转换和审计；
- 修复后将“现象、根因、解决方法、防回归措施”写入项目 `memory.md`；
- 自动化与浏览器回归均需覆盖，尤其验证筛选、翻页后按钮仍有效。

### POOL-03 逐行 PING

- 每一行 IP 的操作区提供独立“PING”按钮，与编辑/详情操作并列。
- 点击后显示“检测中”，完成后显示“可达、不可达、超时或检测失败”，并显示检测时间；可获得时显示耗时。
- PING 只用于网络诊断，不得自动修改 IP 状态、释放分配、驳回申请或触发任何倒计时。
- “可达”只提示可能已被占用；“不可达”不等同于地址必然空闲。
- 后端只能对数据库中现存的 IP 池地址执行检测，不接收任意主机名或命令参数。
- Windows 与麒麟分别使用固定参数列表启动系统 PING，禁止 Shell 字符串拼接；设置超时、并发上限、单用户频率限制并记录审计。
- 审批确认前的 PING 与资源池逐行 PING 复用同一受控服务和结果语义。

### POOL-04 详情

详情至少分为以下区域：

- 网络信息：支行、网点、网段类型、CIDR、IP、网关、DNS；
- 资产信息：科技/非科技、大类、小类、资源编码、PC 使用人信息；
- 申请审批：申请人账号/姓名、申请时间、推荐与最终网段、审批人/时间；
- 状态轨迹：当前状态、人工保留原因、分配与释放信息、最近诊断结果（若本次页面会话中存在）。

## 9. 释放规则

- 科技管理员可对本人名下且当前为 `ASSIGNED` 的 IP 二次确认后立即释放。
- 释放不需要管理员审批、不设倒计时，也不依赖 PING 结果。
- 释放成功后通知所有启用且未删除的管理员。
- 释放、解除 IP/资源编码占用、事件、审计和通知在同一事务完成；重复请求只能成功一次且不得重复通知。
- 管理员强制释放继续保留，必须填写原因并审计。
- 倒计时释放、自动扫描和基于 PING 的自动回收属于未来需求，不纳入本轮。

## 10. 数据导出

导出至少支持以下字段，并允许按固定白名单选择字段：

- 支行、网点、网段类型、CIDR、IP、当前状态；
- 资产大类、小类；
- 科技非 PC 的资源编码；
- PC 使用人姓名、统一认证号；
- 申请科技管理员账号、姓名、申请时间；
- 申请状态、推荐网段、最终网段、改选原因；
- 审批人、审批时间、审批意见；
- 分配时间、释放人、释放时间、释放原因。

继续遵守：CSV 使用 UTF-8 BOM；XLSX 不含宏、公式和外部链接；对公式注入字符做防护；导出动作做权限控制和审计。

## 11. 数据模型与迁移约束

实施时应扩展现有表，不要另建与现有 `ip_assignment` 含义重复的分配表。至少需要表达：

- 地址段类型、同一网点六段分组、规则版本快照；
- 全局规则及其版本；
- 资产大类、小类、启停状态；
- 小类到网段类型的版本化映射；
- 申请的资产分类、条件字段、推荐网段及映射版本；
- 审批的最终网段、改选原因；
- 必要的 PING 审计信息。

数据库约束和服务校验共同保证：

- 同一网点同一有效网段类型只能有一条；
- 有效地址段不得重叠且必须位于全局 `/13` 内；
- PC 与资源编码条件互斥；
- 未配置映射不得提交；
- 历史记录引用的配置和分类不得物理删除。

每个新增迁移脚本必须同时加入应用迁移清单、升级回归、全新库回归和发布包校验。

## 12. 页面设计与兼容性

- 所有新增或修改页面必须先读取并实际使用 Awesome Design skill；在开发记录中说明其对信息层级、条件字段、主从详情、空/加载/失败状态和窄屏布局的影响。
- 保持现有行内管理台视觉风格，不进行无关的大范围换肤。
- 申请表采用分步或渐进式显示，未选择上一步时不展示无关字段。
- 所有按钮都必须有可见反馈：加载、成功、失败或禁用原因，不允许点击无反应。
- 继续使用原生 HTML/CSS/ES5，兼容 IE11/奇安信浏览器；不得引入 Node、CDN 或现代浏览器专属运行时。
- 表格支持分页、跳页和清晰的空状态；详情用弹窗/抽屉承载，键盘可操作且关闭入口明确。

## 13. 安全与运行边界

- 运行环境：麒麟 V10 SP1、ARM64、Java 11；目标机不要求 Maven、MySQL、Node 或 Nginx。
- SQLite 继续限定单机单应用实例、本地磁盘、WAL、外键开启、`busy_timeout`、短事务和应用内写入协调。
- 所有管理、设置、审批、状态修改、PING 和导出接口均在后端执行权限校验，不能只依赖前端隐藏按钮。
- 日志、审计和导出不得记录密码、会话令牌等敏感信息。
- PING 不允许变成任意地址探测器或命令注入入口。

## 14. 自动化和手工验收

1. 先通过第一、第二及当前第三阶段已有回归；

3. 覆盖六段计算、跨第三字节进位、边界、对齐、重叠、原子回滚和配置版本快照；

5. 覆盖推荐网段、管理员改选原因、候选 IP 限域和并发占用；
6. 覆盖编辑状态按钮对应接口与合法/非法状态转换；
7. 覆盖 PING 目标约束、超时、限流和“不改变业务状态”；
8. 覆盖审批历史详情和导出字段完整性、白名单、注入防护；
9. 覆盖直接释放幂等、通知和历史保留；
10. 通过前端 ES5 语法检查、`git diff --check` 和发布包完整性校验。

### 14.2 浏览器手工验收

- 必须实际点击资源池“编辑状态”，验证允许/禁止编辑两类反馈；
- 验证逐行 PING 的加载、四类结果、重复点击控制和状态不被改变；
- 验证支行 → 网点 → 资产类型 → 小类的申请流程和条件字段；
- 验证未配置映射、网点六段不完整时无法提交；
- 验证管理员按推荐网段选 IP，以及改选网段必须填写原因；
- 验证已审批详情、资源池详情、筛选分页和完整导出；
- 验证 760px 以下布局及 IE11/奇安信兼容。

开发机自动化通过不能替代麒麟 ARM64 和 IE11/奇安信实机验收结论。

## 15. 交付要求

最终交付必须包含：

1. 一个自包含 ZIP 压缩包；
2. ZIP 的绝对路径、文件大小、生成时间和 SHA-256；
3. 面向固定目录 `/data/项目/IP管理系统` 的一行自动部署命令，不得出现 `/path/to` 占位符；
4. 升级前备份、安装、验证和回滚说明；
5. 本轮发布说明及按本文编号编写的手工测试清单；
6. 自动化结果摘要，以及尚未执行的麒麟/浏览器实机验收项；
7. 本轮代码提交号和干净度说明，且不得删除用户现有临时目录或附件。

科技资产正式分类表未提供时，交付说明必须明确这一外部依赖，不得宣称科技资产全部分类数据已经验收完成。

## 16. 明确不在本轮范围

- 多分行/多租户；
- 多套全局规则同时生效；
- 倒计时释放、自动扫描、PING 驱动的自动回收；
- 科技资产分类表中尚未提供的小类数据；
- MySQL、Maven、Node、Nginx 作为目标机运行依赖；
- 将旧一对一地址段自动推测并迁移为六段。
